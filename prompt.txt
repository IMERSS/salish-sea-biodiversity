The plan is to turn the salish-sea site into a lightweight index file for the latter two repositories, and a further collection to grow over time. The notion is that all of these projects will be housed in separate repositories, but with a commonly styled navigation banner such that subsidiary sites can return to the index site by clicking top left.

The index site will be configured with a list of repository base URLs for the subsidiary sites, which are expected to house at top level i) a geoJSON file delineating the project boundary, ii) a block of markdown describing the project. When the index file is rebuilt it will traverse the repositories, collecting these files, and then building map-based navigation highlighting them on the map.
The index site need not use the full publication workflow of the subsidiary sites but should use consonant technologies, that is, hugo hextra builds, and the map-libre library for the browseable map.

In place of the placeholder map image, the index site will show an overview of the entire Salish Sea area, with polygons representing the subsidiary projects represented. Tooltips for the polygons will show the markdown block, and clicking on the polygons will browse to the subsidiary site. You can assume that all cooperating sites are housed in GitHub pages built from their docs/ directory and compute all URLs accordingly.
